# Vision3D known limitations

- **Native AR acceptance.** Physical camera scanning, real placement, stable tracking and gestures require a recorded run on iPhone Safari and a compatible Android device. Mobile-sized browser runs and ARKit package checks cover separate prerequisites.
- **Demo hosting.** The public frontend currently relies on a powered Mac and a Cloudflare Quick Tunnel. The connector can reconnect, but a new Quick Tunnel hostname requires a Vercel environment change and redeployment. A named route is supported by configuration and needs an accessible Cloudflare-managed hostname. An external network or tunnel interruption can still delay public requests.
- **Recovery.** A worker protocol failure permits a bounded retry. An API restart marks in-flight or queued jobs as interrupted and removes their transient input. Ask the user to resubmit. SQLite, completed models and unexpired shares persist on the configured disk. The single model worker serializes reconstruction.
- **Rate limiting and direct ingress.** The current tunnel joins visitors in a common socket-peer upload bucket. A trustworthy per-client key needs an authenticated edge or other verified architecture. The API still enforces ownership, upload limits and queue caps. The release candidate disables interactive API documentation in public mode.
- **Single-image geometry.** Hidden faces are inferred and dimensions are uncalibrated. Clear, glossy, thin and cluttered items can fail or produce near-planar output. Mask editing can remove visible artifacts but does not recover missing geometry. Round and Box use explicit procedural shapes.
- **Device resources.** Local inference and browser USDZ conversion depend on available memory. Only the Apple M5 Mac was measured this phase. An AR-capable Android phone also needs the appropriate Google app and Google Play Services for AR.
- **Share scope.** A bearer link grants read-only access until expiry or revocation. Already downloaded files remain with their recipients.
